# 工具调用 Agent 策略集（Function Calling Agent Strategies）

这是一个 Dify Agent 策略插件，提供三种原生函数调用（Function Calling）策略，并由调用方自行控制对话历史。

文中“工具调用”与“原生函数调用（function calling）”指同一能力，本插件在中文界面使用“工具调用”。

三个策略共用同一套模型/工具循环与参数，区别只在于历史如何回放：只回放纯文本问答、不回放历史，或回放完整的工具调用历史。历史窗口由本策略管理，不依赖 Dify 内置的对话记忆。

## 三种策略

| 策略显示名 | 内部 ID | 历史行为 |
| --- | --- | --- |
| 工具调用（问答历史） | `function_calling_text` | 回放此前的用户/助手文本；不回放工具调用与工具结果。 |
| 工具调用（不带历史） | `function_calling_off` | 不回放历史；仍会记录转写，便于之后切换到带历史的策略接续。 |
| 工具调用（完整历史） | `function_calling_full` | 回放文本、助手的工具调用以及工具结果。 |

## 如何选择历史模式

按“下一轮模型需要看到什么”来选，而不是按“能保留多少”来选。

| 场景 | 推荐策略 | 原因 |
| --- | --- | --- |
| 多轮对话，工具调用只是偶尔发生，希望上下文保持干净。 | 工具调用（问答历史） | 回放用户/助手文本，丢掉工具调用轮次，避免旧工具参数挤占提示词。 |
| 单次抽取、分类或路由，每次运行都应独立。 | 工具调用（不带历史） | 不注入历史；仍会记录转写，之后切到带历史的策略可以接续。 |
| 多步工具调用，后一步依赖前面的工具结果或参数。 | 工具调用（完整历史） | 文本、工具调用和工具结果一起回放，模型能接续工具链。 |
| 同一会话里有多个 Agent 节点，职责不同，例如聊天节点和工具节点。 | 按节点分别选择 | 每个节点可以选不同策略。同一会话共用一份转写；模式只改变回放内容，不改变落盘内容。 |
| 排查 Agent 为什么重复或跳过工具调用。 | 工具调用（完整历史） | 工具调用与结果都保留在回放里，链条对模型可见；可配合较小的 `history_turns` 或 `max_history_tokens_k` 控制成本。 |

历史按 Dify 会话保存。Chatflow 或其他能提供 `conversation_id` 的应用可以累积并回放历史。普通 Workflow 的一次性运行没有 `conversation_id`，插件也不会自己创建，因此该次运行不会回放历史。

## 环境要求

- Dify 1.11.2 或更高版本。
- 支持原生工具调用（tool calling）的模型。
- Agent 节点提供的工具。本插件不内置任何工具。
- 插件使用 Dify 的模型调用、工具调用和插件存储 API，无需额外配置网络连接、端点或代理，也不直接发起外部 HTTP 请求。
- 插件会转发工具生成的图片。若工具返回的图片消息文本以 `/files/` 开头，插件可能会读取该本地文件并发送给用户；除此之外不访问文件系统，也不会写入文件。

## 安装

### 从 Dify 市场安装

在 Dify 市场安装 **工具调用 Agent 策略集 / Function Calling Agent Strategies**，然后在 Agent 节点中选择本插件提供的三种策略之一。

### 从本地安装

1. 构建或获取 `function_calling_suite-0.1.1.difypkg`。
2. 在 Dify 中打开 **插件 > 安装插件 > 从本地包安装**。
3. 上传并启用插件。

## 参数

三种策略的参数完全一致。

| 参数 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `model` | 是 | - | 用于原生函数调用的对话模型。 |
| `allowed_tools` | 否 | - | 可选工具名列表。填写后，仅这些工具会暴露给模型并允许执行。 |
| `tools` | 是 | - | Agent 节点提供的工具列表。 |
| `instruction` | 是 | - | Agent 的系统指令。 |
| `context` | 否 | - | 工作流传入的上下文对象。 |
| `query` | 是 | - | 当前用户查询。 |
| `files` | 否 | - | 当前轮的文件。 |
| `history_turns` | 否 | `10` | 历史回放的最大轮数，范围 1-100。一个轮 = 一条用户消息 + 其后所有助手与工具消息。 |
| `max_history_tokens_k` | 否 | `64` | 历史回放预算，以千 token 为单位，范围 1-200。`64` 约等于 64,000 token；按字符粗略估算，不是硬上限。 |
| `maximum_iterations` | 否 | `3` | 模型/工具循环的最大迭代次数，范围 1-500。 |

不带历史模式下，`history_turns` 与 `max_history_tokens_k` 不注入历史，只约束为后续切换到其他策略而保留的转写量。

## 最小 Chatflow 示例

这是一个接线步骤，不是可直接导入的 DSL；节点 ID 和模型提供方与具体环境有关。

```text
开始（sys.query） → Agent（工具调用（完整历史），一个工具） → 直接回复
```

1. 新建 Chatflow，添加 **开始** 节点。
2. 添加 **Agent** 节点，提供方选择 **工具调用 Agent 策略集**。
3. 策略选择 **工具调用（完整历史）**，模型选择支持原生工具调用的模型。
4. 给 Agent 节点添加一个工具，例如时间工具或 HTTP 请求工具；可选地把 `allowed_tools` 设为该工具名。
5. 指令可以写：`需要时调用可用工具；工具失败时说明失败原因。`
6. 把 Chatflow 的用户输入映射到 `query`。
7. 把 Agent 输出接到 **直接回复** 节点并发布。
8. 在同一会话中运行两次。第二次应在 `history_turns` 和 `max_history_tokens_k` 的限制内看到第一次运行的用户、助手和工具轮次。

要对比三种模式，复制这个 Chatflow，只切换策略：

- **工具调用（问答历史）**：保留对话文本，丢掉工具调用轮次。
- **工具调用（不带历史）**：每次运行都不带历史。
- **工具调用（完整历史）**：保留工具链。

插件不内置模型和工具，二者都在 Agent 节点中选择。

## 历史机制

### 存储

插件通过 Dify 的插件存储 API 保存转写，键为：

```text
agent_transcript:{conversation_id}
```

因此：

- 历史按 Dify 会话隔离，不按 Agent 节点隔离。同一会话内使用本插件的多个 Agent 节点共享同一份转写。
- 转写数据保存在运行插件的 Dify 部署内。插件不会把它发送给插件作者或任何第三方。
- 插件不记录消息内容。落盘失败时会记录一条含会话 ID 和异常信息的告警日志，以便发现问题。

### 保留与回放

- 落盘保留量按回放窗口的 3 倍计算，下限 30 轮、绝对上限 500 轮；字符预算由 `max_history_tokens_k` 推算，下限 20,000 字符、上限 2,000,000 字符。
- 落盘裁剪带 1.5 倍滞回，因此数据可能暂时超过目标值，之后才会删除最老的整轮。
- 单条落盘消息上限 8,000 字符；超长内容会在落盘前截断，保留前 70% 和后 30%。
- 回放时从最老的整轮开始丢弃，直到满足轮数与近似 token 预算；若最新一轮单独超出预算，仍会保留该轮。
- 问答历史模式会过滤掉带工具调用的助手消息及其工具结果，避免模型收到孤立的工具调用。
- 不带历史模式仍会记录转写，但不会注入模型提示词。

## 兼容性与限制

- 插件版本：`0.1.1`。
- 最低 Dify 版本：`1.11.2`。
- 插件运行时：Python 3.12，支持 `amd64` 与 `arm64`。
- 所选模型必须支持原生函数调用；仅支持 JSON 模式或纯文本的模型不适用于本策略。
- token 预算为估算值（约每字符 0.6 token），用于约束历史，不是精确计数。
- 历史在同一会话内跨 Agent 节点共享。若需要节点级隔离，请使用不同会话或换用其他插件。
- 只有在 Dify 提供插件存储时才会保存转写；没有存储时运行仍可完成，但不会回放历史。
